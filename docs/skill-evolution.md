# 指南迭代

本项目会随着 ASA API 插件开发经验持续更新，但更新目标是“通用插件开发指南”，不是记录某个私有插件的排错过程。

## 可以沉淀的内容

- 多个 ASA API 插件都能复用的开发流程、检查清单、测试方法。
- 多类插件都会遇到的风险判断，例如 Hook 频率、对象生命周期、状态同步、配置回滚、日志分层。
- 能通过本地 SDK、ASA API wiki、ArkServerApi GitHub 或项目源码确认的 API 事实。
- 经过多场景验证，并写清适用条件和限制的工程模式。

## 不应沉淀的内容

- 单个服务器、单个插件业务、单个作者习惯。
- 私有路径、私有日志、未脱敏崩溃信息、聊天话术、经济数值、奖励配置。
- 某次事故的原始结论。
- 未确认来源的 Hook 签名、字段名、蓝图路径或性能结论。

## 推荐抽象方式

- 从“某个插件这样崩了”抽象成“这种调用链需要验证对象生命周期、回调时机和其他插件共存”。
- 从“某个配置不好用”抽象成“区分服主常调参数和内部技术参数”。
- 从“某个 Hook 在当前版本不可用”抽象成“Hook 签名以本地 SDK 为准，wiki 和源码交叉确认”。
- 从“某次无 crash 断联”抽象成“排查服务器无响应时要采集最后阶段日志、线程/进程状态、插件 debug 和系统资源”。

## 写入前检查

写入文档或 skill 前，确认：

- 这条内容是否适用于不止一个插件。
- 是否写清楚来源、验证方式或适用条件。
- 是否没有把社区常见结构写成官方标准。
- 是否没有泄露私有路径、服务器信息或未脱敏日志。

## 执行规则

ASA 插件开发、排错、审查或发布收尾前，应主动做一次迭代判断，不等用户提醒。

- 结论明显通用、边界清晰、不会暴露私有信息时，直接更新 skill 或指南。
- 只属于当前插件、当前服务器、当前配置或当前业务玩法时，不写入通用 skill；按项目维护文档或长期记忆规则留档。
- 判断不清、可能误导他人、或需要包含项目私有内容时，先向用户确认。
- 更新后在交付说明中写清修改了哪些 skill/docs；如果没有更新，也说明判断为“仅项目内经验”或“无长期复用价值”。

## 同步规则

如果一次排错或开发结论达到了更新 skill 的程度，不要只修改本机已安装的 Codex skill，还要同步修改本指南仓库中的来源文件：

- `skills/asa-api-plugin-dev/SKILL.md`
- `skills/asa-api-plugin-dev/references/*.md`
- 需要面向人阅读时，同步更新 `docs/*.md`

本机 `C:\Users\<User>\.codex\skills\asa-api-plugin-dev` 只是安装后的副本；长期维护应以 `asa-api-plugin-dev-guide` 仓库为准。完成后检查 git diff，必要时提交并推送到远程仓库。

更新已有规则时优先修改原文，不要在其他文件继续追加相反结论。提交前用 `rg` 搜索 `SKILL.md`、`AGENTS.md`、`references` 和 `docs` 中的旧写法、反向结论和重复规则，再执行 `git diff --check`，最后同步本机安装副本。该流程先保持轻量；只有固定检查长期重复且人工经常遗漏时，才增加小型辅助脚本。
