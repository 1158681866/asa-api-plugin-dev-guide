# 配置与命令

## 配置原则

- 默认值保守。
- 高风险功能可关闭。
- 玩家可见文字可改。
- 玩法倍率、概率、列表、文案这类服主常调内容优先配置化。
- 颜色是否配置化取决于插件定位；固定状态语义可以用代码默认值并在文档说明。
- 内部技术参数、临时排错参数、错误配置后风险较高的参数不默认暴露；需要暴露时写清适用场景和安全范围。
- 配置读入时做校验。
- 配置错误要输出明确原因。

## 常见字段

```json
{
  "DebugLogging": false,
  "NotificationMode": "chat"
}
```

## 配置文件分工

发布包常见做法是把运行配置和说明配置分开：

```text
config.json
config说明.json
```

`config.json` 是插件运行时读取的文件，应保持严格 JSON，不写 `//` 注释，避免解析器不兼容。

`config说明.json` 是给服务器管理员看的必需说明文件。它应保留真实配置结构，只在字段旁边补用途、默认值、单位/范围、可选值和必要示例；如果需要，可在开头加一个简短的“插件信息”对象和一条重载方式。

`README.md` 可选，适合写插件总览、安装、命令和排错入口。

只要说明文件里有 `//` 注释，它就不是严格 JSON。插件运行时不应该读取它。

这种分工有几个好处：

- 服务器管理员能直接看懂字段含义。
- 插件读取配置时不依赖 JSONC / 带注释 JSON 解析。
- 更新配置时可以对照说明文件，不容易填错。
- 中文服可以额外提供中文说明，英文服可以保留英文说明。

说明文件只需要写清楚：

- 每个字段的用途和默认值。
- 数值的单位、范围或倍率计算。
- 枚举可选值、列表填写格式和必要风险。

安装流程、固定安全规则、上服验证和其他通用注意事项写在 README 或 wiki，不在 `config说明.json` 里重复。

## 配置说明写法

好的配置说明文件不是只列字段，而是把真实配置复制成一份可参考的样板，让服务器管理员能按结构修改。

推荐内容标准：

```text
1. 保留一份接近真实 config.json 的配置结构
2. 每个字段右侧写一句必要短注释
3. 复杂字段只在相邻位置补一两行说明
4. 倍率、概率、时间这类数值只补单位、范围或必要计算示例
5. 可选添加简短插件信息和重载方式；只在用户明确要求时为指定区域加少量分隔标题，不添加联系方式、命令列表或长注意事项块
```

示例格式：

```jsonc
{
  "插件信息": {
    "名称": "PluginName",
    "版本": "1.0",
    "运行配置": "config.json",
    "重载方式": "PluginName.Reload"
  },
  "Rules": [
    {
      "BlueprintPath": "Blueprint'/Game/.../...'", // 资源蓝图路径，必须完整
      "Name": "显示名称",                          // 只用于备注或日志
      "Enabled": true,                             // true=启用，false=禁用
      "Multiplier": 2.5,                           // 倍率，2.5=250%
      "DurationMinutes": 120                       // 持续时间，单位：分钟
    }
  ]
}
```

字段注释保持一句话；可以保留一个简短插件信息对象和一条重载方式。分隔标题只在用户明确要求时添加，不要追加联系方式或长注意事项尾块。

样式参考只改用户指定的部分。用户只要求参考插件信息时，不要顺带重构下方配置项。

## 字符串模式

模式字段建议转小写：

```text
chat
server
screen
```

未知模式回退到默认值。

## 数值字段

数值字段要限制范围：

- 半径最小值
- 概率 `0.0..1.0`
- 颜色 `0.0..1.0`
- 倍率必须大于 `0`
- 数量必须大于 `0`

## 命令设计

玩家输入的正式聊天命令必须使用 `AddChatCommand` 注册，并在卸载时使用 `RemoveChatCommand` 注销。不要用 `AddOnChatMessageCallback` 自行解析来代替正式命令注册：通用聊天回调即使返回 `true` 阻止了游戏默认广播，也不会把消息标记为正式命令，聊天桥或其他观察插件仍可能把它记录、转发或重新发送。

AsaApi 的正式命令匹配首个 token，命中后执行回调、设置 `command_executed=true`，并在调用游戏原始聊天广播前返回。命令回调本身不需要额外的“隐藏”参数。

命令别名支持热重载时，不要在当前聊天命令回调栈内立即移除或重新注册命令。命令检查会直接遍历命令容器，回调内修改可能导致迭代器失效；应延迟到下一 tick/timer 再同步别名。

推荐玩家命令：

```text
/plugin
/plugin <mode>
/plugin status
/plugin cancel
```

推荐管理员命令：

```text
/plugin reload
Plugin.Reload
```

RCON / 控制台重载可以减少重启服务器次数。

## 命令回执

如果怀疑聊天命令回调重入，可以延迟发送消息，并保存玩家弱引用。
这只是排查手段，不应作为所有插件的固定写法；如果当前接口已稳定，保持简单同步回执即可。

## 对用户解释配置时的中文规则


- 面向中文服主的插件，控制台/cmd日志、RCON回复和 Status 输出也应优先用中文业务含义；英文配置名可以保留，但不要让运行输出只剩英文键值。
和服主/用户沟通时，配置名、Status 字段、日志字段可以保留英文原名，但必须配中文含义。不要只回复 `CleanupScope=CurrentMapOnly`、`Clean=false` 这种英文键值；应写成 `CleanupScope=CurrentMapOnly`：清理范围=当前地图，或 `Clean=false`：该权限组完全免清。

如果用户表示看不懂英文参数，应优先使用中文业务描述，再把英文配置名放在括号里，方便后续定位配置文件。
