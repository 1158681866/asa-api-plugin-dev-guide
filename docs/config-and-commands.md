# 配置与命令

## 配置原则

- 默认值保守。
- 高风险功能可关闭。
- 玩家可见文字可改。
- 颜色、倍率、概率可配置。
- 配置读入时做校验。
- 配置错误要输出明确原因。

## 常见字段

```json
{
  "DebugLogging": false,
  "EnableCommandReply": true,
  "NotificationMode": "chat"
}
```

## 配置文件分工

推荐发布包至少提供两份配置：

```text
config.json
配置说明文件
```

`config.json` 是插件运行时读取的文件，应保持严格 JSON，不写 `//` 注释，避免解析器不兼容。

配置说明文件是给服务器管理员看的，可以写注释、公式、示例、命令和注意事项。很多插件会把 `config.json` 复制一份，命名成 `config-commented.json`、`config说明.json` 或类似名字，然后在里面直接写说明。这个文件名和 `.json` 后缀不是标准；真正有价值的是它保留了真实配置结构，并在结构旁边解释每个字段怎么改。

只要说明文件里有 `//` 注释，它就不是严格 JSON。插件运行时不应该读取它。

这种分工有几个好处：

- 服务器管理员能直接看懂字段含义。
- 插件读取配置时不依赖 JSONC / 带注释 JSON 解析。
- 更新配置时可以对照说明文件，不容易填错。
- 中文服可以额外提供中文说明，英文服可以保留英文说明。

说明文件里建议写清楚：

- 每个字段的用途。
- 默认值代表什么。
- 数值倍率如何计算。
- 修改后是否需要重载或重启。
- 对应的 RCON / 控制台命令。

常见命名：

- `config说明.json`
- `config-commented.json`

命名可以按项目习惯来，但 README 里要写清楚：插件真正读取的是 `config.json`。

## 配置说明写法

好的配置说明文件不是只列字段，而是把真实配置复制成一份可参考的样板，让服务器管理员能按结构修改。

推荐内容标准：

```text
1. 文件顶部写插件名、配置文件名、常用命令
2. 保留一份接近真实 config.json 的配置结构
3. 每个字段右侧写短注释
4. 复杂字段后面单独写字段说明
5. 倍率、概率、时间这类数值写计算公式和示例
6. 最后写注意事项和重载方式
```

示例格式：

```jsonc
{
  // ==================== 功能配置 ====================
  "Rules": [
    {
      "BlueprintPath": "Blueprint'/Game/.../...'", // 资源蓝图路径，必须完整
      "Name": "显示名称",                          // 只用于备注或日志
      "Enabled": true,                             // true=启用，false=禁用
      "Multiplier": 2.5,                           // 倍率，2.5=250%
      "DurationMinutes": 120                       // 持续时间，单位：分钟
    }
  ]
}

// ==================== 字段说明 ====================
//
// BlueprintPath    : 游戏资源蓝图路径，必须与游戏资产路径一致。
// Name             : 备注名称，不参与逻辑判断。
// Enabled          : 单条规则开关。
// Multiplier       : 倍率。最终值 = 原始值 x Multiplier。
// DurationMinutes  : 持续时间，单位分钟；0 或缺省表示不自动结束。
//
// ==================== 计算示例 ====================
//
// 想要 250%：
// Multiplier = 250 / 100 = 2.5
//
// 想要 50%：
// Multiplier = 50 / 100 = 0.5
//
// ==================== 常用命令 ====================
//
// 插件重载：PluginName.Reload
//
// ==================== 注意事项 ====================
//
// 1. 修改 config.json 后再执行重载命令。
// 2. 说明文件只是参考，不会被插件读取。
// 3. 不要把真实 token、密码、Webhook 地址写进示例。
```

字段注释建议短，详细解释放到下方说明区。这样配置块仍然容易复制，说明也不会挤在一行里看不清。

## 字符串模式

模式字段建议转小写：

```text
chat
server
screen
```

未知模式回退到默认值。

## 数值字段

数值字段要限制范围：

- 半径最小值
- 概率 `0.0..1.0`
- 颜色 `0.0..1.0`
- 倍率必须大于 `0`
- 数量必须大于 `0`

## 命令设计

推荐玩家命令：

```text
/plugin
/plugin <mode>
/plugin status
/plugin cancel
```

推荐管理员命令：

```text
/plugin reload
Plugin.Reload
```

RCON / 控制台重载可以减少重启服务器次数。

## 命令回执

命令回执建议可配置：

```json
"EnableCommandReply": true
```

如果怀疑聊天命令回调重入，可以延迟发送消息，并保存玩家弱引用。
这只是排查手段，不应作为所有插件的固定写法；如果当前接口已稳定，保持简单同步回执即可。
