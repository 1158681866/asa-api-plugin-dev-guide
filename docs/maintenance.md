# 维护规范

这个仓库按长期开发手册维护。目标不是堆资料，而是把可复用的 ASA API 插件开发方法整理成可执行流程、检查清单和模板。

## 收录标准

适合收录的内容：

- 已验证的 Hook 用法或避坑结论。
- 崩服、无响应、加载失败、功能不生效的排错路径。
- 插件发布、测试、打包、回滚流程。
- 配置字段设计、命令设计、通知方式等可复用约定。
- 与其他 ASA 插件共存时的兼容结论。

不收录：

- 没验证的猜测。
- 只对某一台服务器成立的临时路径。
- 未脱敏的 crash 包、token、IP、密码。
- 已被新方案替代但没有标注状态的旧做法。

## 更新旧内容

发现旧结论过期时，优先修改原文，不要只在新文件里追加反向结论。

写法示例：

```text
已废弃：旧方案在当前场景依赖高频扫描，实测有性能风险。
现用方案：改为事件 Hook 触发，只在短时间窗口内重试。
```

## 文档风格

- 中文优先。
- 步骤要能照着做。
- 风险要说明触发条件。
- API、Hook、类名、函数名保留英文原名。
- 不把“可能、也许、大概”写成确定结论。

## 版本维护

- 文档结构变化：更新 `docs/README.md`。
- 新增发布要求：更新 `docs/release-checklist.md`。
- 新增稳定性建议：更新 `docs/stability.md` 和 `docs/debugging.md`。
- 新增默认项目结构：更新 `docs/project-structure.md` 和模板说明。

## 仓库维护

- 使用 issue 记录排错和文档改进。
- 使用 PR 记录结构化修改。
- 每次 release 打 tag，tag 名建议使用 `v0.1.0` 这种格式。
- 避免提交敏感信息，因为内容可能被复制到插件项目或公开文档。
