# 稳定性建议

本页是工程建议，不是 ASA API Wiki 的接口规范。具体插件是否需要使用某类 Hook 或 native call，要按本地 SDK、插件目标和服务器实测判断。

## 需要评估的操作

- 大范围 actor 扫描
- 高频全局 Hook
- 递归访问 UObject 路径或 Outer 链
- 会触发蓝图、事件、复制同步的 setter / sync 调用
- 全局脚本派发 Hook
- Hook 内大量日志
- Hook 内复杂 IO
- 循环里频繁 `ForceNetUpdate()`

这些不是“绝对禁止”，也不代表所有插件都应避开。采用前建议记录：

- 为什么业务上需要它。
- 触发频率大概是多少。
- 作用范围如何限制。
- 如何通过日志或测试证明它生效。
- 出问题时如何关闭或回滚。

## 为什么危险

### 对象路径和 Outer 链

路径类函数可能沿 UObject Outer 链继续访问对象。对象生命周期不稳定时，风险会被放大。

### setter / sync 调用

一些看起来只是“改数值”或“同步状态”的函数，可能触发：

- 状态变化事件
- 蓝图逻辑
- UI 更新
- 复制同步
- 其他插件 Hook

### 高频全局 Hook

触发频率越高，插件里的小成本越容易被放大，也更容易造成服务器无响应。是否可接受取决于逻辑复杂度、调用频率和服务器负载。

## 评估思路

- 优先确认是否已有更贴近业务事件的 API 或 Hook。
- 目标对象能从 Hook 参数获得时，通常比后续大范围查找更容易控制范围。
- 如果需要重试，给重试次数、时间窗口和日志。
- 如果需要 timer 或高频 Hook，先估算每次执行成本。
- 给高风险或争议性功能加配置开关，便于隔离测试。

## 日志策略

好日志：

```text
命令#12 阶段=保存选择前
命令#12 阶段=保存选择后，结果=成功
事件处理 阶段=字段写入前
事件处理 阶段=字段写入后
```

坏日志：

```text
每 tick 输出所有 NPC
每次高频事件都输出完整对象信息
循环里刷几百行无筛选日志
```
