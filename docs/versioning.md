# 版本策略

## 起始版本与 API 版本

- 新插件的 `PluginInfo.Version` 默认从 `1.0` 开始。
- `PluginInfo.Version` 表示插件自身版本，`PluginInfo.MinApiVersion` 表示最低 AsaApi 版本；两者互相独立，不能因为最低 API 是 `2.0` 就把新插件版本直接写成 `2.0`。
- 插件尚未正式发布、仍处于同一轮开发或测试时，重新构建、重新打包、修改配置结构都不自动增加版本号；先保持 `1.0`，正式发布后再根据已发布基线判断下一版本。
- 两个字段都必须是 JSON number，例如 `Version: 1.0`、`MinApiVersion: 2.0`。

## 语义化版本

推荐使用：

```text
MAJOR.MINOR.PATCH
```

- `MAJOR`：破坏性配置变更、重构主链路、删除兼容行为。
- `MINOR`：新增功能、配置项、可选能力。
- `PATCH`：修 bug、文档补充、稳定性小改。

## 插件版本记录

每次发布至少记录：

- 版本号
- DLL 时间
- 配置变化
- Hook 变化
- 风险点变化
- 上服测试结果

## 配置兼容

新增配置项时：

- 代码有默认值。
- 旧配置缺字段也能加载。
- 文档说明默认行为。

删除配置项时：

- 文档明确废弃。
- 代码不再读取。
- 包内默认配置移除。

## 发布包命名

面向服主的正式公开包，默认使用稳定的中文展示名：

```text
中文插件名.zip
飞升部落清理插件.zip
```

- 文件名不重复版本号、作者、`Release`、日期或临时后缀；更新时以同名正式包替换旧包。
- 版本号以 `PluginInfo.Version`（必须是 JSON number）为准，AsaApi 会在加载日志中显示。ZIP/DLL SHA256、生成时间和验证结果写入包外发布记录或交付说明。
- `PluginInfo.Description` 使用字段分隔格式：`展示名 · 核心功能 · 作者：署名[ · QQ：公开号码]`，默认示例为 `PluginName · 核心功能说明 · 作者：示例作者`；不要在 Description 再次重复版本号。只有作者明确要求公开时才追加 QQ，且发布前必须确认 QQ 不与本机凭据、Token 等敏感值冲突；若冲突，应改用其他联系方式或先更换真实凭据，不能为保留联系方式而放宽泄漏检查。
- 包内的文件夹、DLL 和 `PluginInfo.FullName` 继续使用稳定英文内部标识，不因公开包名而改动。

测试包或内部归档可以带时间：

```text
PluginName-test-20260623-1720.zip
```
