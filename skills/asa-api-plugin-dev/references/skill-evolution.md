# 技能与指南迭代

用于把实际开发、排错、发布中的经验沉淀回通用 Agent Skill 或公开指南。目标是让指南越来越专业，但不被单个项目、单个 Agent 客户端或单套工具带偏。

## 可以写入

- 多个 ASA API 插件可复用的流程、检查项、验证方法。
- 多类插件通用的风险评估问题，例如 Hook 触发频率、对象生命周期、配置发布、回滚方式。
- 本地 SDK、ASA API wiki、ArkServerApi GitHub 或项目源码可确认的 API 事实。
- 多场景验证过、并写清适用条件的工程模式。

## 不写入

- 单个服务器、单个插件业务规则、单个作者习惯。
- 具体插件名、私有路径、聊天话术、经济数值、奖励表。
- 某次崩溃的原始结论，除非已经抽象成诊断步骤。
- 未确认来源的 Hook 签名、字段名、蓝图路径或性能结论。

## 抽象方式

- 把具体对象名抽象成对象来源、生命周期、归属关系和验证方式。
- 把具体崩溃抽象成“最小复现、阶段日志、对象有效性、调用链影响”的排查流程。
- 把具体配置争议抽象成“哪些给服主调、哪些应固定为内部实现”的配置设计原则。
- 把单次兼容问题写成“可能与其他插件共享调用链时需要隔离验证”，不要点名单个第三方插件。

## 更新检查

写入前确认：

- 内容是否适用于不止一个插件。
- 是否有来源或验证方式。
- 是否没有暴露私有路径、服务器信息、未脱敏日志。
- 是否没有把社区习惯写成官方标准。

## 执行规则

- 每次 ASA 插件开发、排错、审查或发布收尾前，主动执行本检查，不等用户提醒。
- 结论明显通用、边界清晰、不会暴露私有信息时，直接更新 skill 或指南。
- 只属于当前插件、当前服务器、当前配置或当前业务玩法时，不写入通用 skill；按项目维护文档或外置脑规则留档。
- 判断不清时，把待写内容压缩成一两句话说明风险，向用户确认后再写。
- 更新后在最终回复中说明改了哪些 skill/docs；如果没有更新，也说明判断为“仅项目内经验”或“无长期复用价值”。

## 一致性检查

- 指南仓库中的 `skills/asa-api-plugin-dev` 是长期权威来源；任何 Agent 客户端的个人或项目安装目录都只是部署副本。
- 修改一条已有规则时，优先修正原文；随后使用当前环境可用的搜索能力检查 `SKILL.md`、平台适配器、`references` 和 `docs` 中的旧写法、反向结论与重复规则。
- 权威源位于 Git 仓库时，提交前执行 `git diff --check`。同步部署副本前先检查本地差异；有独立修改时采用三方合并或保留冲突，不得整目录强制覆盖。
- 如果当前只能访问部署副本，先定位其权威仓库。无法定位或无写权限时，生成候选补丁或待同步项，不猜测其他 Agent 的安装目录，也不把部署副本声称为已更新的公共来源。
- 一致性检查先保持为轻量搜索和人工判断；只有固定检查长期重复且经常遗漏时，才增加小型脚本，不为指南维护建设独立平台。
