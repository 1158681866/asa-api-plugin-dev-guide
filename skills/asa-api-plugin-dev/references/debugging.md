# 排错

## 有 crash 栈

收集或检查：

- `crashcallstack.txt`
- 最新 `ArkApi_*.log`
- 同时间段服务器游戏日志
- 插件 DLL 时间、配置和包路径
- ASA 服务端版本和 AsaApi 版本

把栈映射到插件阶段：加载 Hook、命令回调、timer、事件 Hook、资源/库存、通知。

## 无 crash 的无响应或断联

如果服务器进程还在但客户端超时：

- 给命令或事件加唯一 id 的阶段日志。
- 只在可疑调用前后打日志。
- 不要在循环里刷大量日志。
- 收集无响应前最后一条插件日志。
- 用配置开关一次只关闭一个风险功能测试。

## 服务器不在本机

明确区分“本地编译/测试通过”和“服务器实测通过”。交付包后，列出服务器侧需要检查的日志和效果，例如：

- 插件加载 Hook 已启用。
- 命令已执行到预期阶段。
- 事件 Hook 已触发。
- 属性/功能已应用。
- 已知错误日志没有再出现。

## 隔离套路

1. 先确认服务器加载的是最新 DLL，可以看时间戳或版本/启动日志。
2. 关闭一个可选功能。
3. 复测同一个动作。
4. 恢复后再关下一个嫌疑点。
5. 最后只保留稳定的最小路径。
