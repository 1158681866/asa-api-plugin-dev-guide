# 稳定性建议

本页是工程建议，不是 ASA API Wiki 的接口规范。ASA 服务器插件可能没有清晰 crash 栈就崩服或无响应；风险操作要尽量小、可观察、可关闭。

## 需要评估

- 用 timer 大范围扫描 actor。
- 宽泛高频全局 Hook。
- 对可能失效或临时对象调用 UObject 路径链、Outer 链函数。
- 在 Hook 里调用重型脚本、事件、网络同步函数。
- 在聊天命令回调里发送 UI/聊天通知时，注意对象生命周期和回调链路。

## 高风险类别

- setter / sync 类调用，可能触发内部脚本、UI、复制同步或其他插件 Hook 链。
- 全局脚本 Hook，尤其当其他插件也 Hook 脚本派发时。
- 循环里反复 `ForceNetUpdate()`。

这些不是默认禁止，也不代表所有插件都应避开。采用前说明业务必要性、触发频率、范围限制、可观测日志和回滚方式。

## 评估做法

- 如果 Hook 参数直接提供目标对象，通常先评估能否直接使用它。
- 字段写入、脚本调用、同步调用都要说明验证方式。
- 初始化有延迟时，重试应有次数上限和日志。
- 延迟任务里注意对象生命周期。
- 测试期给争议性功能加配置开关。

## 兼容其他插件

如果其他插件在你的某个调用后立刻报错，先用“前/后”日志定位最后一个触发点，再移除或配置化该调用。
