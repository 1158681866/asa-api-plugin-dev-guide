# 稳定性建议

本页是工程建议，不是 ASA API Wiki 的接口规范。ASA 服务器插件可能没有清晰 crash 栈就崩服或无响应；风险操作要尽量小、可观察、可关闭。

## 默认避免

- 用 timer 大范围扫描 actor。
- 宽泛高频全局 Hook。
- 对可能失效或临时对象调用 UObject 路径链、Outer 链函数。
- 在 Hook 里调用重型脚本、事件、网络同步函数，除非已经实测安全。
- 在聊天命令回调里同步发送 UI/聊天通知；能延迟一 tick/一秒就延迟发送。

## 高风险类别

- setter / sync 类调用，可能触发内部脚本、UI、复制同步或其他插件 Hook 链。
- 全局脚本 Hook，尤其当其他插件也 Hook 脚本派发时。
- 循环里反复 `ForceNetUpdate()`。

这些不是绝对禁止；如果插件功能必须使用，先限制范围、加开关、加阶段日志，再上服验证。

## 优先做法

- 使用游戏 Hook 参数里直接传入的对象，不要后续再搜索。
- 在头文件和上服日志验证后，使用最小范围字段写入。
- 官方初始化有延迟时，对同一个对象做有次数上限的短重试。
- 延迟任务里用弱引用，避免玩家/对象失效。
- 测试期给高风险功能加配置开关。

## 兼容其他插件

如果其他插件在你的某个调用后立刻报错，先用“前/后”日志定位最后一个触发点，再移除或配置化该调用。
